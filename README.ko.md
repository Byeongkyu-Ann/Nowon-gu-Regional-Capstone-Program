# Re:Hand — 착용형 손가락 재활 로봇의 안전 제약 제어 소프트웨어

Re:Hand는 저비용 와이어 구동 소프트 글러브형 손가락 재활 로봇의 제어 소프트웨어입니다.
**H.O.P.E Hand** 프로젝트를 이어서 발전시킨 것입니다. 하드웨어 구조는 같습니다. UHMWPE 와이어를 서보모터 2개가 당기고, 플렉스 센서와 FSR 근력 모듈로 측정하며, Arduino Nano가 제어합니다. 가장 큰 변화는 제어기입니다. 기존 LinUCB 속도 선택기를 **SafeLadderTS**로 바꾸었습니다. SafeLadderTS는 안전 제약 톰슨 샘플링이며, 통증을 보상 신호로만 쓰지 않고 안전 제약으로 다룹니다.

광운대학교 지역밀착형 캡스톤 디자인 프로그램(대상 지역: 서울 노원구)을 위해 개발했습니다.

## 5. 빠른 시작

```bash
# 시뮬레이션 모드 UI (하드웨어 불필요)
python main.py --sim

# 실제 로봇과 UI
python main.py --real

# 콘솔 테스트: 환자 P1, 빠른 시작, 10사이클, 가상 시간 가속
python main.py --sim --headless --mode quick --patient P1 --cycles 10

# 콘솔 테스트: 전체 캘리브레이션과 치료
python main.py --sim --headless --mode full --cycles 20

# 알고리즘 벤치마크
python benchmark.py --cycles 40 --seeds 100
```

`main.py` 옵션:

| 옵션 | 의미 |
|---|---|
| `--sim` / `--real` | 시뮬레이션 또는 실제 하드웨어를 강제합니다. `config.SIMULATION_MODE`보다 우선합니다. |
| `--headless` | UI 없이 실행합니다. `--sim`에서만 지원합니다. |
| `--mode full\|quick` | 캘리브레이션 후 치료, 또는 저장값만 사용합니다. |
| `--patient ID` | 환자 식별자. 프로필 파일을 정합니다. |
| `--cycles N` | N사이클 후 종료합니다. |
| `--minutes M` | 세션 길이(분). 기본값은 30입니다. |
| `--speedup X` | 헤드리스 가상 시간 배속. 기본값은 40입니다. |

## 6. 시뮬레이션 모드와 실제 하드웨어 모드

기본 스위치는 `config.py`에 있습니다.

```python
SIMULATION_MODE: bool = False   # True: 가상 로봇·환자. False: 시리얼로 Arduino 연결.
```

명령행 옵션 `--sim`, `--real`이 이 값을 덮어씁니다. 시뮬레이션 모드에서는 다음과 같이 동작합니다.

- 가상 로봇이 서보 움직임과 센서값을 재현하므로 세션 로직이 그대로 실행됩니다.
- 가상 환자는 위치에 따라 속도 허용치가 다릅니다. 가동범위 양 끝에서 허용치가 낮습니다.
- 속도가 허용치를 넘으면 시그모이드 위험률로 통증이 시작됩니다. 안전한 사이클이 쌓이면 허용치가 서서히 올라갑니다.
- `sim.auto_patient`가 `True`이면 가상 환자가 스스로 통증 버튼을 누릅니다.
- `sim.auto_confirm`으로 캘리브레이션 확인 버튼을 자동으로 넘길 수 있습니다.

환자 모델은 **알고리즘 비교를 위한 가정**이며 임상 데이터가 아닙니다.

## 7. 세션 흐름

```
대기 -> 캘리브레이션 -> 치료 준비 -> 치료 중 -> 종료
                                        |
                                        +----> 중단   (비상정지, 통신 두절, 소프트웨어 오류)
```

**전체 모드**

1. 모터 가동범위. 2번 모터가 신전 와이어를 당겨 운영자가 손이 완전히 펴졌다고 확인할 때까지 진행합니다. 이어서 1번 모터가 굴곡 와이어를 당겨 주먹이 완전히 쥐어질 때까지 진행합니다. 두 동작 모두 느리게(20 deg/s) 당깁니다.
2. 센서 기준값. 각 모터가 한계 위치로 움직이고, 폄과 굽힘 위치에서 플렉스 센서를 1초간 평균합니다.
3. 근력. 환자가 FSR 모듈을 5초간 쥡니다. 평균 FSR 값으로 기본 속도 `k0`가 정해집니다(9장 참조).
4. 유효성 검사. 모터 이동량이 10 deg 미만이거나 플렉스 센서 변화량이 60 ADC 카운트 미만이면 캘리브레이션을 중단합니다.
5. 프로필을 저장하고 치료 사이클을 시작합니다. 시간 제한이나 `max_cycles`까지 진행합니다.

**빠른 시작 모드**

1. `data/profiles/<환자>.json`을 불러옵니다.
2. 캘리브레이션이 14일보다 오래되었으면 경고를 표시합니다.
3. 저장된 프로필이 없으면 보수적 기본값으로 시작합니다. 두 모터 이동량 45 deg, 가동범위 0.6, 기본 속도 15 deg/s입니다.
4. 처음 2사이클은 속도 상한을 낮춥니다(`warmup_max_arm = 1`).

**치료 1사이클**은 굴곡 단계와 신전 단계로 이루어집니다. 각 단계는 4개 구간으로 나뉩니다. 구간 경계마다 에이전트가 속도를 고릅니다. 환자는 통증 버튼으로 결과를 알립니다.

| 단계 | 의미 | 시스템 반응 |
|---|---|---|
| 0 | 통증 없음 | 안전 통과로 기록합니다. |
| 1 | 뻐근함 | 약한 벌점. 안전 점수가 20% 줄어듭니다. |
| 2 | 통증 | 즉시 30% 속도로 복귀하고, 해당 구간 속도 상한을 낮추며, 3사이클 쿨다운에 들어갑니다. |

사이클이 끝날 때 통증 2가 없었다면 가동범위가 2% 늘어납니다. 통증 2가 있었다면 시작 비율로 초기화됩니다.

## 8. 안전 설계

| 장치 | 내용 |
|---|---|
| 긴급정지 3경로 | Space 키(전역 단축키), 화면 긴급정지 버튼, 로봇 본체의 물리 버튼입니다. 모두 모터를 멈추고, 2,500 ms 동안 부저를 울리고, 안전 위치로 복귀한 뒤 리포트를 저장합니다. |
| 하드웨어 비상정지 | Arduino가 PC를 기다리지 않고 스스로 서보를 멈추고 부저를 울리며 `EVT,ESTOP`을 보냅니다. 입력은 20 ms 디바운스합니다. |
| 하트비트 감시 | PC가 0.5초마다 `HB`를 보냅니다. Arduino가 2,000 ms 동안 아무것도 받지 못하면 서보를 멈추고 부저를 울립니다. PC도 2초 동안 수신이 없으면 통신 두절로 판단합니다. |
| 슬루율 제한 | 펌웨어가 10 ms마다 서보 각도를 갱신하며 명령 속도를 넘지 않습니다. |
| 속도 사다리 | 에이전트는 이미 안전하다고 검증된 가장 빠른 속도의 바로 위 한 단계까지만 시도합니다. |
| 통증 후 복귀 | 통증 2가 나면 현재 속도의 30%로 낮추고, 해당 구간 속도 상한을 낮추며, 3사이클 쿨다운을 시작합니다. |
| 안전 점수 | 초기값 0.8. 통증 2 후 0.4배, 통증 1 후 0.8배가 됩니다. 통증 2 없이 사이클을 마치면 0.05 오릅니다. 범위는 0.1~1.0입니다. 속도 선택의 통증 허용치를 조절합니다. |
| 가동범위 제한 | 캘리브레이션 범위의 0.8에서 시작합니다(프로필이 없으면 0.6). 통증 2 없는 사이클마다 0.02씩 늘어 최대 1.0입니다. |
| 과굴곡 보호 | 플렉스 값이 캘리브레이션 범위를 10% 넘으면 해당 구간을 종료합니다. |
| 캘리브레이션 검사 | 센서 변화량이나 모터 이동량이 비정상이면 중단합니다. |
| 오래된 캘리브레이션 | 저장된 값이 14일보다 오래되면 경고합니다. |
| 보수적 기본값 | 프로필이 없으면 저속·소범위로 시작합니다. |
| UI 안전 | 긴급정지 버튼은 항상 같은 위치에서 가장 크게 표시됩니다. 모든 버튼이 키보드 포커스를 받지 않으므로 Space 키가 엉뚱한 버튼을 누르지 않습니다. |

## 9. SafeLadderTS 알고리즘

SafeLadderTS는 **통증 확률이 허용치 이하인 가장 빠른 속도**를 찾습니다. 컨텍스트마다 따로 학습합니다.

**컨텍스트.** 한 방향(굴곡 또는 신전)의 한 구간입니다. 2 × 4 = 8개입니다.

**팔(arm).** 속도 후보는 `k0 + {0, 10, 20, 30}` deg/s이며 상한은 100 deg/s입니다. 기본 속도 `k0`는 캘리브레이션 악력에서 정해집니다. `k0 = clip(int(FSR/1023 · 45) + 15, 15, 80)`입니다. 악력이 강할수록 사다리가 더 빠른 속도에서 시작합니다. 프로필이 없으면 `k0 = 15`입니다.

**상태.** 컨텍스트 `c`와 팔 `k`마다 통증 확률의 Beta 사후분포 파라미터 `(f[c,k], s[c,k])`를 유지합니다. 사전값은 `f0 = 0.5`, `s0 = 1.5`입니다.

**선택** (컨텍스트 `c`):

1. 통증 허용치: `ε = 0.20 · max(S, 0.3)`. `S`는 안전 점수입니다.
2. 검증된 팔 `k_cert`: 안전 관측이 3.0회 이상이고 사후 평균 통증이 0.15 이하인 가장 빠른 팔입니다.
3. 사다리 상한: `k_cap = min(k_cert + 1, k_pain)`. `k_pain`은 이 컨텍스트의 이전 통증 2로 정해진 속도 상한입니다.
4. 각 팔에서 `p̃[k] ~ Beta(f[c,k], s[c,k])`를 뽑습니다.
5. `k ≤ k_cap`이고 `p̃[k] ≤ ε`인 가장 빠른 팔을 고릅니다. 하나도 없으면 가장 느린 팔을 고릅니다.

**갱신** (팔 `k`의 결과 `y ∈ {0, 1, 2}`):

- `y = 0`: `s[c,k] += 1`, 더 느린 팔 `j < k`는 `s[c,j] += 0.5`.
- `y > 0`: `f[c,k] += w`, 더 빠른 팔 `j > k`는 `f[c,j] += 0.5·w`. 뻐근함은 `w = 1`, 통증은 `w = 2`.
- `y = 2`: `k_pain = k − 1`로 낮추고 3사이클 쿨다운을 시작합니다.

**사이클 종료.** 쿨다운이 끝나면 속도 상한이 한 단계 올라갑니다. 모든 증거는 `γ = 0.99`로 사전값 쪽으로 할인되어, 환자 상태가 바뀌면 오래된 관측이 서서히 잊힙니다.

**변수 표**

| 기호 | 의미 | 단위 |
|---|---|---|
| `c` | 컨텍스트 (방향 × 구간) | 없음 |
| `k` | 속도 팔 인덱스 | 없음 |
| `s`, `f` | Beta 사후분포의 안전·통증 증거 | 횟수 |
| `S` | 안전 점수 | 없음, 0.1~1.0 |
| `ε` | 통증 확률 허용치 | 확률 |
| `γ` | 사이클당 할인율 | 없음 |

단조 전파는 속도가 빠를수록 통증 위험이 줄지 않는다고 가정합니다. 수동적 손가락 운동에서는 합리적이지만 가정입니다.

`agent.py`의 `LinUCBAgent`는 이전 프로젝트의 기준선입니다. 벤치마크 비교에만 사용합니다.

## 10. 시리얼 프로토콜과 펌웨어

시리얼 링크는 115,200 bps, ASCII, 한 줄에 명령 하나입니다. 기본 포트는 `COM3`입니다. 포트를 찾지 못하면 Arduino를 자동으로 탐색합니다(`serial.auto_detect`).

**PC → Arduino**

| 명령 | 의미 |
|---|---|
| `M<n>,<angle>,<speed>` | n번 서보를 `angle` [deg]로 `speed` [deg/s]에 맞춰 이동합니다. |
| `STOP` | 모든 서보를 현재 위치에서 멈춥니다. |
| `BUZ,<ms>` | `ms` 밀리초 동안 부저 경보 패턴을 울립니다. |
| `HB` | 하트비트. 다른 명령을 받아도 감시 타이머가 초기화됩니다. |

**Arduino → PC**

| 메시지 | 의미 |
|---|---|
| `DATA,<flex>,<fsr>` | 50 ms마다 ADC 원시값을 보냅니다. |
| `EVT,ESTOP` | 하드웨어 비상정지 버튼이 눌렸습니다. 누르는 동안 반복해서 보냅니다. |

**펌웨어 핀 배치 — 가정값입니다.** 로봇에 전원을 넣기 전에 실제 배선과 대조하세요.

| 기능 | 핀 |
|---|---|
| 서보 1 (굴곡) | D9 |
| 서보 2 (신전) | D10 |
| 플렉스 센서 | A0 |
| FSR | A1 |
| 비상정지 버튼 | D2와 GND 사이, `INPUT_PULLUP`, 눌림 = LOW |
| 부저 | D8 |

서보 초기 각도는 `config.py`의 `m1_init = 0`, `m2_init = 180`과 같아야 합니다. 기존 스케치에 안전 기능만 합치려면 비상정지, 부저, 하트비트 부분을 복사해 넣으면 됩니다.

세션이 끝나면 다음 파일이 저장됩니다.

## 13. 벤치마크

`benchmark.py`는 하드웨어 없이 가상 환자에서 정책들을 비교합니다.

**설정**

- 환자 속도 허용치는 40, 55, 70 deg/s입니다. 가동범위 양 끝에서 최대 40% 낮아집니다.
- 통증 위험률은 `h = h0 · σ((v − v_tol) / β)`이며 `h0 = 3.0`/s, `β = 4.0` deg/s입니다.
- 팔은 37, 47, 57, 67 deg/s. 단계당 4개 구간. 실행당 40사이클.
- 100 시드 × 3 허용치 = 정책당 300회 실행.
- 리그렛 `= Σ [ max(0, v* − v) / v* + 0.5·1(y=1) + 2.0·1(y=2) ]`. `v*`는 오라클 속도입니다.

**비교 정책:** SafeLadderTS, LinUCB, 사다리 제거 SafeLadderTS, 단조 전파 제거 SafeLadderTS, 고정 저속·중속·고속.

**주요 결과 (시뮬레이션만)**

| 정책 | 실행당 통증 2 횟수 | 표준편차 | 오라클 대비 속도 |
|---|---|---|---|
| SafeLadderTS | 7.5 | 10.3 | 0.94 |
| LinUCB | 20.6 | 29.4 | 1.03 |
| 사다리 제거 SafeLadderTS | 11.9 | — | — |
| 단조 전파 제거 SafeLadderTS | 7.7 | — | — |
| 고정 저속 | 7.2 | — | 0.88 |
| 고정 중속 | 25.1 | — | — |
| 고정 고속 | 62.2 | — | — |

- SafeLadderTS는 LinUCB보다 통증 2를 13.1회(64%) 줄입니다. 차이의 95% 부트스트랩 신뢰구간은 −16.6~−9.6입니다.
- 속도 비율이 1.0을 넘으면 환자 허용치보다 빠르게 구동했다는 뜻입니다. LinUCB는 평균 1.03입니다.
- 사다리를 제거하면 1~10사이클의 통증이 1.86회에서 5.47회로 늘어납니다. 초기 안전은 사다리가 지킵니다.
- 단조 전파를 제거해도 결과는 거의 같습니다. 이 시뮬레이션에서는 전파의 이점이 확인되지 않았습니다.

**허용치별 실행당 통증 2 횟수**

| 허용치 | SafeLadderTS | LinUCB |
|---|---|---|
| 40 deg/s | 21.4 | 58.3 |
| 55 deg/s | 0.7 | 3.6 |
| 70 deg/s | 0.4 | 0.0 |

결과는 `data/benchmark/benchmark.json`과 `benchmark.png`에 저장됩니다. 벤치마크를 다시 실행하면 이 파일이 덮어써집니다. 위 숫자는 `--seeds 100` 기준입니다.

## 14. 한계

1. **시뮬레이션만 수행했습니다.** 실제 환자가 사용한 적이 없습니다.
2. **유리한 환자 모델.** 가상 환자와 SafeLadderTS 모두 통증 위험이 속도에 따라 단조 증가한다고 가정합니다.
3. **허용치 40 deg/s의 바닥 효과.** 가장 느린 팔(37 deg/s)도 가동범위 양 끝에서는 허용치를 넘습니다. 그래서 모든 정책에서 통증이 약 21회 남습니다. 속도 하한을 낮춰야 합니다.
4. **허용치 70 deg/s의 탐색 비용.** SafeLadderTS는 탐색 때문에 통증 0.4회를 겪습니다. 이 환자에서 LinUCB와 고정 저속은 0회입니다.
5. **플렉스 센서 1개.** 각도 오차가 장갑 착용과 센서 위치에 좌우됩니다. 보조 센서는 구현하지 않았습니다.
6. **통증 버튼 의존.** 버튼을 누르기 어려운 환자는 지원하지 않습니다. 근전도 보조 신호는 향후 추가할 수 있습니다.
7. **가정된 펌웨어 핀.** 실제 배선과 대조해야 합니다.
8. **의료기기가 아닙니다.** 임상 사용에는 윤리 심의, 임상 평가, 의료기기 인허가가 필요합니다.
